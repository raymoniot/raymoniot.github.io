      固件发布

      功能概述 link

      固件发布用于把新固件测试通过之后再下发给现场设备，完整流程是：

      新增固件包 → 上传新版本 → 测试 → 灰度发布（可选）→ 最终发布

      设备侧通过固件检测参数按需检测新版本，只有最终发布的版本才会对全部设备生效；灰度阶段只有加入灰度名单的设备能取到灰度版本。

      与「工具箱 → 固件管理」的区别：固件管理是平台上的固件文件库（搜索、新增、修改、删除、下载、授权、兑换码），本页是把某个固件包按流程发布给设备的操作台。

      1.界面说明 link

      • 入口：工具箱 → 固件发布
      • 每个固件包显示为一张卡片：固件名、已发布版本号（绿色标签）、未发布版本号（蓝色标签）、启用开关、修改固件包、版本历史、固件 Bundle ID（鼠标悬停可复制）、固件说明
      • 卡片右下角的按钮会随流程状态变化：上传新版本 / 撤销 / 重新上传 / 开始测试 / 灰度发布 / 测试通过，点击发布!
      • 右上角的「+」卡片用于新增固件包
      • 不同角色看到的按钮不同：开发可以上传新版本、撤销、重新上传；测试可以开始测试、操作灰度名单；负责人可以启用/停用固件包、修改固件包、灰度发布和最终发布

      2.新增固件包 link

      点击「+」新增固件包，需要填写：

      • 固件 Bundle ID：必填，格式为 <设备类型>.<厂商>.<型号>[.附加信息]，只能使用小写字母、数字和点，长度不超过 32 位（示例：test.1、r1.raymon.501.0）
      • 固件名：必填，1–40 个字符
      • 固件说明：必填，说明这个固件包是什么设备的固件

      创建后卡片右上角的开关用于启用/停用该固件包。停用后设备检测这个固件包会直接失败（提示 bundle was inactive），适用于临时下线某个固件包。

      固件包与设备的对应关系 link

      设备通过两个参数到平台检测固件：固件检测URL 与 固件检测BundleID（参数编号一般是 896001 / 896003）。设备检测时会带上自己的序列号和当前版本，平台按 Bundle ID 找到对应固件包并判断是否有更高版本。

      3.上传新版本 link

      在固件包卡片上点击「上传新版本」：

      1. 上传固件文件：仅支持 bin、hex 格式；同一份固件（内容 MD5 相同）不能重复上传，会提示「不能上传相同的固件！」
      2. 填写版本号：格式为 X.X.X（三段数字，例如 4.2.1），上传后不可修改
      3. 填写更新日志：必填，一行一条，发布时会按编号展示给使用者；页面上方会显示上一版本号供参考
      4. 点击确认完成上传，卡片上会出现蓝色的「未发布版本号」标签

      此时可以对该版本执行：撤销、重新上传、开始测试。

      4.测试 link

      点击「开始测试」打开「固件测试」抽屉，包含两个标签页：

      • 工作区：左侧显示本次固件的变更日志；右侧填写测试日志并点击保存

      • 固件升级：按 序列号、状态、所属电站、标签 筛选设备，勾选测试设备后点击「固件升级」把固件下发给测试设备

        • 只有在线设备能下发；如果勾选了离线设备，会提示「请确认所选设备都在线」
        • 设备列表支持分页（每页 100 / 500 / 1000 条）

      测试完成后点击抽屉底部的「测试通过」并确认：

      • 必须先填写测试日志，否则会提示「请填写测试日志」
      • 测试日志在待测试状态可以随时修改保存，测试通过之后就不能再改

      撤销与重新上传 link

      • 撤销：删除本次未发布的固件，同时清除这次固件的测试日志和灰度名单（不可恢复），卡片回到「未上传新版本」状态
      • 重新上传：版本号不变，替换固件文件并修改更新日志（用于固件文件传错或需要补充日志的情况）

      5.灰度发布 link

      测试通过后，卡片上会出现「灰度发布」和「测试通过，点击发布!」两个按钮。

      1. 点击「灰度发布」打开灰度名单
      2. 在左侧设备列表（可按序列号、状态、所属电站筛选）勾选设备，点击「新增」把它们加入灰度名单，最多 100 台
      3. 右侧是已加入灰度的设备，显示序列号与成功次数；勾选后可以批量移除
      4. 灰度名单只在测试通过之后、最终发布之前可以修改

      灰度的含义：处于灰度阶段时，名单内的设备检测到的是灰度版本，名单外的设备仍然使用已发布版本。这样可以在少量设备上先验证新固件是否稳定，再决定是否全量发布。

      6.最终发布 link

      点击「测试通过，点击发布!」，核对变更日志、测试日志以及开发/测试人员和对应时间，再点击「最终发布」：

      • 发布后：版本号变成绿色的「已发布版本号」，未发布版本消失，灰度名单清空
      • 该版本对全部设备生效：设备下次检测固件时如果自身版本低于该版本，就会提示有新版本
      • 历史版本不会丢失，可在「版本历史」中查看

      7.版本历史 link

      点击固件包卡片右上角的时钟图标打开版本历史：按时间倒序展示每个版本，包含版本号与状态、开发/测试/发布人员及时间、变更日志、测试日志。

      注意事项 link

      • 撤销不可恢复：会同时删除测试日志与灰度名单，请谨慎操作
      • 一个固件包同一时间只能有一个未发布版本；发布或撤销之后才能上传下一个版本
      • 设备能检测到固件的前提：固件包处于启用状态、且设备参数中的「固件检测BundleID」与该固件包一致
      • 部署到设备时只会更新比设备当前版本更高的版本
      • 最终发布会立即影响线上设备，请确认测试与灰度结果都符合预期
